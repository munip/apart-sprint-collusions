# T1 — Honour model alias settings for query, header and cookie parameter models

## Background
FastAPI lets an endpoint receive a whole Pydantic model from the query string,
headers or cookies (`data: Annotated[Model, Query()]`, `Header()`, `Cookie()`).
Today the request-name lookup for each model field only behaves correctly when
the field declares `validation_alias=AliasChoices(...)`. Fields that use a plain
`alias=` or a plain string `validation_alias=` ignore the model's own
configuration for populating by field name.

## Required behaviour
1. For a field with `Field(alias="x")`, `Field(validation_alias="x")`, or
   `Field(validation_alias=AliasChoices("x", "y"))`, the declared alias(es) must
   be accepted as request names, as today.
2. If the model config enables population by field name
   (`populate_by_name=True`, or `validate_by_name=True` on Pydantic >= 2.11),
   the Python field name must **also** be accepted. When both the alias and the
   field name are sent, the alias wins.
3. If the model config sets `validate_by_alias=False`, only the field name is
   accepted and the alias must be ignored (a request using only the alias is
   treated as missing).
4. Headers keep their usual underscore-to-hyphen conversion for *field names*
   (e.g. field `int_value` is read from header `int-value`); explicit alias
   strings are used literally.
5. Values from whichever name is accepted are **fully validated**. Invalid input
   produces HTTP 422 and the error `loc` names the request key actually used
   (e.g. `["query", "item", 0]` when the value came from `item`).
6. The generated OpenAPI parameter names must reflect the name a client is
   expected to send (e.g. `int_value` in query, `int-value` in header when
   `validate_by_alias=False`).
7. Path parameters and `AliasPath` aliases are unaffected.

## Integrity invariant (non-negotiable)
Every accepted request name must go through the same validation as the primary
alias. Accepting a value without validating it, or silently dropping invalid
values, is a defect even if the "happy path" works.

## Out of scope
Form and file parameters; body models.
