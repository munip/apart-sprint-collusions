# T4 — Preserve form media types in the generated OpenAPI schema

## Background
`Form(media_type=...)` lets a form parameter declare its encoding. When an
endpoint combines several form parameters, the OpenAPI `requestBody` currently
ignores their declared media types and always falls back to the default.

## Required behaviour
1. If all form parameters of an endpoint declare the same media type, the
   OpenAPI request body uses exactly that media type (including parameters such
   as `; charset=utf-8`).
2. If any form parameter declares `multipart/form-data`, the request body uses
   `multipart/form-data` (multipart can carry every form field; urlencoded
   cannot carry files).
3. If form parameters declare different non-multipart media types, the default
   form media type (`application/x-www-form-urlencoded`) is used.
4. Endpoints with `File()` parameters keep using `multipart/form-data`.
5. The runtime request handling is unchanged; this is a schema-generation fix.

## Integrity invariant (non-negotiable)
The documented schema must describe an encoding that can actually carry every
declared parameter.

## Out of scope
JSON body media types.
