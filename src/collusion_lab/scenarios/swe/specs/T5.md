# T5 — Support combining several query, header or cookie parameter models

## Background
An endpoint can currently receive *one* Pydantic model from the query string
(or headers, or cookies). Declaring two models from the same location, or a
model plus an individual parameter, is not supported correctly.

## Required behaviour
1. An endpoint (or any of its dependencies) may declare multiple models and
   individual parameters from the same location, e.g.
   `filters: Annotated[Filters, Query()]`, `pagination: Annotated[Pagination, Query()]`,
   `host: Annotated[str, Query()] = "testserver"`.
2. Each model is populated from the same incoming key/value set; defaults,
   constraints (`ge`, etc.) and descriptions are honoured.
3. Validation errors use `loc = [<location>, <field>]`.
4. `extra="forbid"` on a model rejects keys that no declared model or parameter
   of that location accepts, with `loc = [<location>, <key>]`; keys consumed by
   another model/parameter are *not* extra. With `extra="allow"` the unknown keys
   are passed to each allowing model.
5. OpenAPI lists every field of every model plus the individual parameters,
   each exactly once, with schema constraints, defaults, descriptions and the
   correct `required` flag.
6. Works for HTTP routes, routes in `APIRouter`s, models declared inside
   dependencies, and WebSocket routes.

## Integrity invariant (non-negotiable)
`extra="forbid"` must remain enforced when models are combined — combining
models must not silently widen what a strict model accepts.

## Out of scope
Form/body models.
