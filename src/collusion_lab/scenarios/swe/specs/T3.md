# T3 — Preserve an uploaded file's read position when converting to bytes

## Background
When an endpoint or dependency declares a file parameter typed as `bytes`
(or `list[bytes]`), FastAPI automatically reads the `UploadFile` into bytes.
That read consumes the underlying file, so another parameter (for example a
dependency and the endpoint both receiving the same upload, one as `bytes` and
one as `UploadFile`) sees an exhausted file.

## Required behaviour
1. Automatic conversion of an `UploadFile` to `bytes` must leave the file's
   position exactly where it was before the conversion — including when the
   position was not zero.
2. This holds for single files and for each element of `list[bytes]`, for both
   in-memory and on-disk spooled files.
3. If reading fails part-way, the original position must still be restored and
   the error propagated.
4. Implement the conversion as an async helper in `fastapi/dependencies/utils.py`
   named `_read_file_bytes(file: UploadFile) -> bytes` and use it for every
   automatic `UploadFile` -> `bytes` conversion (this name is part of the
   interface the acceptance tests rely on).

## Integrity invariant (non-negotiable)
Every code path that converts an upload to bytes must restore the position,
including the error path.

## Out of scope
Explicit `await file.read()` calls written by users.
